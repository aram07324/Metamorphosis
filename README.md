# Metamorphosis

Metamorphosis is an original AI assistant and workflow-automation application. The foundation and **Milestone 2: Chat Engine** are implemented. The app is for local development and is not production-ready; authentication, tenant isolation, and workflow execution are not implemented.

## Implemented

- FastAPI service with versioned health and readiness endpoints.
- SQLAlchemy 2.x and SQLite with foreign-key enforcement, WAL mode, and additive Alembic migrations.
- Next.js dashboard and interactive chat at `/chat`; prior conversations persist and can be renamed, archived, or deleted.
- Ollama is the default provider for new configurations; it sends the system prompt and recent conversation history to the configured local model and streams generated tokens through SSE.
- The deterministic mock provider remains available by explicitly setting `AI_PROVIDER=mock`; Ollama failures never silently switch to mock.
- The app starts if Ollama is absent, reports provider/model availability, and never downloads a model automatically.
- Markdown and GFM rendering without enabling raw HTML; context token estimation and bounded recent-history selection.
- Backend and frontend tests run without paid APIs or network access after dependencies are installed.

## Requirements

- Windows 10/11
- Python 3.12 or newer (the current development environment uses Python 3.13)
- Node.js 20.9 or newer (Node.js 22 is recommended)
- npm

## Run on Windows

Open two PowerShell terminals from this project directory.

### Backend

```powershell
cd backend
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item ..\.env.example .env }
alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

If PowerShell blocks activation, use `.\.venv\Scripts\python.exe` instead of activating the environment. The backend listens on `http://127.0.0.1:8001`; interactive API documentation is at `http://127.0.0.1:8001/docs`. Port 8000 may be occupied by other local projects.

### Frontend

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local
npm run dev
```

Open `http://localhost:3000`, then choose **AI assistant** or open `http://localhost:3000/chat`. The browser calls `http://127.0.0.1:8001/api/v1`. Port 8000 may belong to another local project.

### Configure the real local AI provider (Ollama)

Ollama is selected for new configurations. To install it on Windows, use the official Ollama PowerShell installer:

```powershell
irm https://ollama.com/install.ps1 | iex
```

This installer and model download require internet access. After installation, open a new PowerShell terminal and verify the CLI:

```powershell
ollama --version
```

The Ollama Windows app normally starts its local service. If the service is not already running, start it in a separate terminal and leave that terminal open:

```powershell
ollama serve
```

In another terminal, inspect available models. The list may initially be empty:

```powershell
ollama list
```

For an 8 GB RAM computer, `qwen2.5:3b` is the configured local model. Pull it only if it is not already shown by `ollama list`, then verify the exact installed tag:

```powershell
ollama pull qwen2.5:3b
ollama list
```

Model download requires internet access and disk space; check the current model library for the selected tag's download size. Ollama must show the tag in `ollama list` before it is considered installed.

Edit the existing `backend\.env` (do not replace other settings such as the database URL). Set `OLLAMA_MODEL` to the exact tag shown by `ollama list`, and select Ollama:

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:3b
PROVIDER_CONNECT_TIMEOUT_SECONDS=5
PROVIDER_TIMEOUT_SECONDS=90
CHAT_CONTEXT_TOKENS=4096
CHAT_RESERVED_OUTPUT_TOKENS=512
```

Stop the existing backend with `Ctrl+C`, then restart it after editing the configuration. From the project root, run these commands in the backend terminal:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

Verify that Ollama reports the configured model as available:

```powershell
$provider = Invoke-RestMethod http://127.0.0.1:8001/api/v1/chat/provider
$provider | Format-List
if ($provider.provider -ne "ollama" -or -not $provider.available) {
    throw "Ollama or the configured model is unavailable. Check ollama serve, ollama list, and OLLAMA_MODEL."
}
```

Continue only when the response shows `provider: ollama` and `available: True`. Open `http://localhost:3000/chat`, start a new conversation, and send a prompt that asks for an explanation or a follow-up question. The response is generated by the installed Ollama model; the chat page shows the selected provider and model. If the provider is offline or the model tag is missing, the UI shows an error and retry control instead of returning a mock answer.

You can also verify a real response directly through the SSE API from PowerShell:

```powershell
$conversation = Invoke-RestMethod `
    -Uri http://127.0.0.1:8001/api/v1/conversations `
    -Method Post `
    -ContentType "application/json" `
    -Body "{}"
$headers = @{ "Idempotency-Key" = [guid]::NewGuid().ToString() }
$response = Invoke-WebRequest `
    -Uri "http://127.0.0.1:8001/api/v1/conversations/$($conversation.id)/messages/stream" `
    -Method Post `
    -Headers $headers `
    -ContentType "application/json" `
    -Body '{"content":"Explain what a context window is in two sentences."}'
$response.Content
```

The SSE body should contain `meta`, one or more `delta`, then `done` events. Confirm `available: True` and an `ollama` provider before treating the returned text as a genuine local-model response.

To intentionally use the offline deterministic provider instead, set `AI_PROVIDER=mock` in `backend\.env` and restart the backend. The UI will label it `mock`.

### Troubleshooting

- **Provider says offline:** Confirm the Ollama app/service is running, then check `http://127.0.0.1:11434/api/tags`. The Ollama CLI may be unavailable in the current PowerShell `PATH` even while its local HTTP service is reachable.
- **Model unavailable or not found:** Compare `OLLAMA_MODEL` in `backend\.env` with the exact installed tag in `ollama list` (or `/api/tags`). Pull a model explicitly only when you choose to download it.
- **Settings appear unchanged:** Restart the backend after editing `backend\.env`; settings are loaded when the process starts. Verify with `/api/v1/chat/provider`.
- **Frontend cannot connect:** Keep the backend on `127.0.0.1:8001` and frontend on `localhost:3000`; do not move Metamorphosis to port 8000.

## Configuration

The backend reads `backend/.env` (see [`backend/.env.example`](./backend/.env.example)). SQLite is the default. New configurations select `AI_PROVIDER=ollama`; existing `.env` files keep their current values and must be edited explicitly. `AI_PROVIDER=mock` selects the offline deterministic provider. Ollama connection timeout is configured with `PROVIDER_CONNECT_TIMEOUT_SECONDS`; `PROVIDER_TIMEOUT_SECONDS` configures read/write timeouts. `CHAT_CONTEXT_TOKENS` and `CHAT_RESERVED_OUTPUT_TOKENS` control context and maximum generated output. Set `DATABASE_URL` to a SQLAlchemy-compatible PostgreSQL URL and install an appropriate PostgreSQL driver to use PostgreSQL; PostgreSQL operation has not yet been integration-tested. CORS origins are configured using a JSON array in `CORS_ORIGINS`.

Chat API routes include `/api/v1/conversations`, `/api/v1/conversations/{id}/messages`, `/api/v1/conversations/{id}/messages/stream`, and `/api/v1/chat/provider`. The stream uses `meta`, `delta`, `done`, and `error` SSE events. The default local approximation estimates one token per four characters; it is not an exact model tokenizer. System prompt and expected output capacity are reserved before selecting recent messages.
